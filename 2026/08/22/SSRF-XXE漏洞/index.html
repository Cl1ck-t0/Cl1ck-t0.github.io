SSRF&XXE漏洞

SSRF和XXE的共同点是：用户表面上提交的是一个地址或一段数据，但程序却让服务器替用户访问了内部资源。

一、前置知识

1.1 漏洞概述

什么是 SSRF？

  • SSRF（Server-Side Request Forgery，服务端请求伪造）

  • 服务器根据用户输入去请求某个地址，但没有限制好访问范围

  • 攻击者让服务器替自己访问内部资源

    SSRF 形成的原因大都是由于服务端提供了从其他服务器应用获取数据的功能且没有对目标地址做过滤与限制。
    比如,黑客操作服务端从指定URL地址获取网页文本内容，加载指定地址的图片，下载等等。利用的是服务端的请求伪造。ssrf是利用存在缺陷的web应用作为代理攻击远程和本地的服务器

什么是 XXE？

  • XXE（XML External Entity，XML 外部实体注入）
  • 服务器解析 XML 时，允许 XML 中定义并使用外部实体
  • 攻击者让解析器替自己读取文件或访问网络

核心思想：

SSRF = 借用服务器的网络身份去访问资源
XXE = 借用 XML 解析器的能力去读取/请求资源

1.2 两个漏洞的核心区别

维度 SSRF XXE
入口 URL 参数 XML 数据
触发点 HTTP 请求函数 XML 解析器
核心能力 让服务器发起任意请求 让解析器读取文件/发起请求
常见目标 内网、本机、云元数据 本地文件、内网

重要：XXE 可以造成 SSRF（见 3.3 节）

二、SSRF 服务端请求伪造

2.1 常见场景

开发人员可能用这类功能来做：

没有任何过滤限制

2.3 有回显 vs 无回显

类型 特征 利用方式 难度
有回显 服务器请求的内容直接返回到页面响应中 直接读取文件内容、服务信息 较低
无回显（Blind SSRF） 页面不返回请求内容，但服务器确实发起了请求 通过响应时间、HTTP 状态码、DNS 日志判断 较高

无回显场景下的探测技巧：

  1. 访问自己控制的服务器，查看访问日志
  2. 利用 dict:// 或 gopher:// 协议与内网服务交互，观察响应差异
  3. 通过响应时间判断端口是否开放（开放通常更快响应）

2.5 SSRF 防御方案

优先级 防御措施 说明
第一 不让用户直接控制完整 URL 使用白名单让用户选择预定义 URL
第二 协议白名单 仅允许 http/https
第三 域名白名单 仅允许访问指定的域名
第四 端口白名单 仅允许 80、443 等常用端口
第五 对解析后的真实 IP 校验 检查是否为内网地址，防范 DNS 重绑定
第六 禁止访问本机/内网/云元数据 设置网络黑名单
第七 限制服务器网络出口 防火墙控制出站流量
第八 禁止或严格校验重定向 设置不跟随重定向，或检查每个跳转目标

四、常见问题

4.1 基础概念问题

Q: SSRF 为什么是"借服务器访问资源"？

因为 SSRF 是利用服务器的网络权限去发起请求。服务器通常能访问内网、本机服务等用户无法直接访问的资源，攻击者通过控制 URL 参数，让服务器替自己去访问这些资源。

Q: SSRF 有回显和无回显有什么区别？

  • 有回显：服务器请求的内容直接返回在响应中，可以直接读取数据
  • 无回显：页面不返回内容，需要通过响应时间、状态码、DNS 日志等间接判断

Q: XXE 中的实体是什么？

实体是 XML 中的"宏"或"变量"，用 &实体名; 引用，解析时会替换成定义的内容。外部实体可以引用外部资源（如本地文件、URL）。

Q: 为什么 XML 解析器可能读取本地文件或访问网络？

因为 XML 标准支持外部实体（SYSTEM 关键字），如果解析器没有禁用这个功能，当解析到 <!ENTITY name SYSTEM "file:///etc/passwd"> 时，就会去读取文件。

4.2 检查与绕过问题

Q: URL 过滤为什么不能只靠字符串匹配？

因为同一个地址可以有无数种写法。例如 127.0.0.1 可以写成 127.1、2130706433、0x7F000001，还可以用域名解析到内网地址。字符串匹配很容易被绕过。

Q: XXE 为什么可能造成 SSRF？

因为 XXE 的外部实体可以指定为一个 URL（如 http://169.254.169.254/latest/meta-data/），解析器访问这个 URL 时，就触发了 SSRF。所以 XXE 不仅可以读文件，也可以让服务器访问内网资源。

4.3 利用链问题

Q: SSRF 的核心问题清单是什么？

  1. 服务器能访问哪些用户无法直接访问的地址？
  2. 能否访问本机服务？
  3. 能否访问内网服务？
  4. 返回内容会不会显示在页面上？
  5. 即使没有回显，能否通过其他方式判断？
  6. 服务器支持哪些协议？

Q: 为什么 XXE 带外攻击需要两个步骤？

因为参数实体（%file）的值无法直接在同一个文档中通过 HTTP 发送出去（某些 XML 解析器的限制）。所以需要：

  1. 先加载外部 DTD（%dtd）
  2. 在外部 DTD 中再发请求（%send），携带文件内容

4.4 防御问题

Q: SSRF 和 XXE 分别应该如何防御？

漏洞 核心防御
SSRF 白名单 + 网络隔离，不让用户控制完整 URL
XXE 禁用外部实体解析，禁用 DOCTYPE

Q: 为什么不能只靠一道过滤规则？

SSRF 需要多层防御：协议限制、域名白名单、端口白名单、内网 IP 黑名单、重定向检查。

XXE 也需要多层防御：禁用外部实体、禁用 DTD、使用安全解析器配置。

纵深防御原则：任何一道防线都可能被绕过，多层检查提高安全性。

DNS Rebinding出现的根本原因，在于 浏览器同源策略只检查域名，不检查 IP，而 DNS 解析结果又是可以动态变化的。攻击者正好利用这两点之间的缝隙，绕过同源策略，访问你内网里的设备。

而TTL之所以重要，是因为它代表了浏览器多久重新解析一次页面内容，倘若TTL过长，攻击者的恶意js无法及时被触发，导致攻击过程被延长，倘若DNS TTL被设置为0或者很短的时间，那么攻击者就可以在浏览器二次解析之前替换掉请求的IP为内网，通过攻击者服务器内部恶意js脚本，通过img，fetch等读取受害者内网响应的内容。
