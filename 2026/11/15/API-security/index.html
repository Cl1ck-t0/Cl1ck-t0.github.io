API security

一、基础知识

API (Application Programming Interface)

应用程序编程接口 是一个软件与另一个软件互动的方式。如果一个程序或应用程序有 API，外部客户端可以向它请求服务。

API 安全是保护 API 免遭攻击的过程。正如应用、网络和服务器可能会遭受攻击一样，API 也可能陷入许多不同的威胁，成为此类威胁的受害者。

API 安全是 Web 应用安全的核心组成部分。大多数现代 Web 应用依赖 API 来运行，而 API 允许外部方访问应用，这会给应用带来额外的风险。举例来说，企业向公众开放其办公室：这样一来，办公室内的人员增加，其中一些人可能不为公司员工所知，这会增加风险。同样地，API 允许外部人员使用程序，也会给 API 服务的基础设施带来更多风险。

开始之前我们先看看

OWASP API Security Top 10 是 OWASP 专门针对 API 风险发布的清单，与 Web Top 10 互补：Web 版覆盖通用 Web 应用，API 版更关注对象级授权、业务流、第三方依赖这些 API 特有的问题。当前最新版本是 2023 版。

编号 名称 含义
API1 Broken Object Level Authorization（BOLA） 只校验“能否调用接口”，不校验“能否操作这个对象”；替换 ID 就能越权读写他人数据。这是 API 场景中最常见的问题
API2 Broken Authentication 认证机制缺陷：无鉴权、弱口令、Token 可预测或不过期、JWT 签名不校验
API3 Broken Object Property Level Authorization 响应返回过多敏感字段（Excessive Data Exposure），请求中可批量赋值（Mass Assignment）。2023 版把这两项合并
API4 Unrestricted Resource Consumption 缺少速率限制、分页上限和请求体大小限制，可以被大量请求耗尽资源或当作 DoS 入口
API5 Broken Function Level Authorization 普通用户能调用管理员或内部接口，即功能维度的垂直越权
API6 Unrestricted Access to Sensitive Business Flows 不防护业务逻辑滥用：批量注册、撞库、抢购脚本、薅羊毛
API7 Server Side Request Forgery（SSRF） 服务端按用户传入的 URL 发请求，可用于探测或攻击内网、访问云元数据
API8 Security Misconfiguration CORS 配置过于宽松、默认配置、调试接口暴露、错误信息泄露、缺少 TLS
API9 Improper Inventory Management 旧版本 API、影子 API、测试环境的 API 无文档也无监控，已被遗忘但仍在线
API10 Unsafe Consumption of APIs 在使用第三方 API 时盲目信任其返回数据，导致二次注入、开放重定向等问题

二、靶场实战

本文的主要内容，还是在实操中对api security的内容做出实践性阐述。

首先我们先试试/api

发现返回了大量的错误信息：包括服务器的绝对文件路径和版本，部署位置，暴露了具体的路由文件和抛出错误的代码，以及技术栈和框架内部的调用链。

这个现象属于 API8:2023 Security Misconfiguration（安全配置错误），具体是“错误处理不当导致敏感信息泄露”

为什么会这样呢？

因此确认了技术栈为express+node

暴露路由文件划分（angular.js、verify.js、insecurity.js）

修复思路：

1、将/api /rest这种不存在的接口返回内容被访问时返回标准的JSON404，而不是抛出异常；

2、统一错误处理中间件，客户端只返回通用型错误信息，不暴露敏感错误信息；
